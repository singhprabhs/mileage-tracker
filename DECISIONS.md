# Decisions

One line per decision made without the user, with the reason.

- Used Vite base path `/mileage-tracker/` and `HashRouter` — the brief names `mileage-tracker` as the repo and requires hash-based routing for GitHub Pages.
- PWA manifest references `pwa-192x192.png`, `pwa-512x512.png` and `pwa-maskable-512x512.png`, but the PNG icon files land in Phase 4 — Phase 1 is setup only and ships no binary files.
- Domain code uses the brief's snake_case leg field names (`odo_start`, `from_type`, `parking_cents`) — they mirror the database tables, so later phases need no field translation.
- Odometer and parking helpers throw `RangeError` on invalid input (non-digits, negative previous reading, non-integer cents) — pure functions cannot show UI errors, and throwing keeps invalid values out of stored data.
- A leg's "same pair" for the 3x-median warning is matched on `from_name` + `to_name` — the brief says "the same two places" and names are the place identity available on a leg.
- Locked-leg handling for a Home–Office distance change is modelled with an optional `locked` flag and stored values on `StoredLeg` — days carry the lock in Phase 2, and this keeps the recalculation rule unit-testable now.
- CI runs on Node 20 and 22 — 20 is the current GitHub Actions LTS baseline and 22 is the active LTS.
- No Dexie, Supabase, Geoapify, PDF or Excel dependencies were installed in Phase 1 — they belong to Phases 2, 3 and 5 and keeping them out keeps Phase 1 minimal.
- Phase 2 Dexie schema is version 1 with only profiles, locations, days and legs — the sync outbox table is Phase 4, so no unused table ships early.
- The local profile is a single row keyed by user_id; before sign-in it uses a locally generated UUID and is re-keyed to the signed-in user's id on the next save — this is a one-user app, so there is never more than one profile row to reconcile.
- Office name and address live on the Office row in locations (profile carries only office_location_id, exactly like the Supabase schema) — one source of truth for addresses, and Settings edits update that row in place.
- The best-effort Supabase profile backup sends office_location_id as null in Phase 2 — locations only exist on the server once sync lands in Phase 4, and sending a local-only id would break the foreign key.
- Sign-in is email magic link only (signInWithOtp) — the brief allows magic link or password, and magic link means no password to store or reset.
- When VITE_SUPABASE_URL / VITE_SUPABASE_ANON_KEY are unset, the Supabase client is null and the app runs fully locally with a clear "not set up" message — dev and tests must never need real credentials.
- Today's primary button is derived from the open day's state: no open day → Start Day; open day whose last stop is not Home → Log Stop (with an End Day button beside it); open day whose last leg already ends at Home → End Day, which opens the summary to review and close — "End Day" on Today means finishing the day, and the End Day screen is the log-the-Home-stop path.
- Undo snapshots live in memory only (a Map keyed by a token carried in router state) and hold the one most recent change per navigation — Phase 4 sync will give changes a durable outbox, and a 10-second undo window never needs to survive a reload.
- Recent parking chips come from the user's own stored legs (Dexie, across all days): the 3 most recent distinct amounts and the 5 most recent distinct notes, most recent first — no separate recents table to keep in sync.
- A logStop / insertLeg whose parking is over $100.00 writes nothing and returns a needs-confirmation result; the UI confirms and re-calls with parking_confirmed — the confirmation rule lives in the service, so no caller can bypass it by accident.
- Vitest blanks VITE_SUPABASE_URL / VITE_SUPABASE_ANON_KEY / VITE_GEOAPIFY_API_KEY in vitest.config.ts — unit tests stay deterministic on machines whose local .env holds real public keys, and never build a live client by accident.
- Phase 4 outbox has no coalescing: one item per change with that write's full snapshot, replayed in queue order — volume is tiny for one user, and replaying every snapshot in order is correct by construction.
- Pull never overwrites a record that still has a pending outbox item (local pending wins until pushed, then the next pull sees it) — a queued local edit must never be clobbered by the older server copy of the same record.
- The needs_review flag set when a pulled merge breaks a day's leg chain is local-only: it lives on the local day row, is stripped from Supabase payloads, and is recomputed after every merge of that day's legs — the server schema has no such column and the flag is derived state, not user data.
- The Add to Home Screen hint shows on every non-standalone browser, not only iOS Safari (with Share-sheet wording when an Apple mobile user agent is detected) — platform detection is unreliable, and the brief's intent is getting the app installed so its storage is not cleared.
- A sync run that hits a 3-times-failed item leaves it queued and locked until the user presses Retry on Today (which resets attempts) — automatic runs never hammer a failing item, and the error stays visible instead of failing silently.
- The Supabase keepalive workflow ships as docs/keepalive-workflow.yml and must be copied to .github/workflows/keepalive.yml by hand once — the automation account for this repo cannot write files under .github/workflows/ (the same restriction as ci.yml in Phase 1).
- The brief's Playwright airplane-mode test (tests-e2e/offline.spec.ts, `npm run test:e2e`) runs and passes locally with headless Chromium; it stays out of the Vitest run and the GitHub CI unit job (browsers are a separate heavy download), and seeds its profile straight into IndexedDB because e2e cannot sign in.
- Sync push is dependency-ordered (locations → profiles → days → legs, stable queue order within an entity), superseding the Phase 4 "replayed in queue order" line — the server enforces foreign keys (profiles.office_location_id → locations, legs.day_id → days), so a child queued before its parent failed with an FK violation and deadlocked the queue (the reported "27 changes waiting" bug).
- Sync failures are contained per record, superseding the Phase 4 "locks until Retry" line: a failed or locked item blocks only later items for the same record and its dependents (a profile on its Office location, legs on their day); locked items are skipped by automatic runs, keep surfacing as an error in the status, and independent records keep syncing.
- Sync runs backfill before pushing: the first run does a full scan and enqueues any local record with no pending item (gated by the meta flag backfillV2CompletedAt); later runs enqueue-if-missing only for records updated after lastSyncAt and never for versions the server already has (updated_at at or below lastPulledAt), and a pending leg/profile always drags its day/Office location into the queue — records written before the outbox existed (Dexie v1) have no outbox entries, and idempotent UUID upserts make a redundant enqueue harmless.
- Items locked on a foreign-key error get their attempts reset automatically once per engine lifetime (once per app load/update) — those locks were caused by push ordering, which the fix removes, so the already-stuck queue recovers on the next ordinary sync run; locks from any other error still wait for the user's Retry.
- History and reports read the local Dexie database only (never Supabase) — the brief makes the phone the source of truth, and a report must work in airplane mode.
- Report writers share one pure buildReportModel (rows + totals via the domain module); PDF/Excel/CSV only format it — the numbers are sacred, and the model is unit-testable without generating files.
- The PDF header block is drawn with jsPDF rects/text over the same column widths as the trip table instead of a second autotable — the sample's header merges cells across table columns, and matching column edges matter more than autotable's cell model allows.
- In Excel the Total Claimable / Total Parking header values are SUM formulas over the table columns (and Distance is =odo_end - odo_start per row), not stored numbers — the brief requires the totals to compute when the file is opened, and a formula can never disagree with the rows above it.
- No Total Distance line was added to any report — the sample and the brief's header spec have only Total Claimable (plus Total Parking when parking exists), and adding a line would change the report layout.
- CSV dates are yyyy-mm-dd while PDF/Excel display "Jul 02" (Excel stores real dates formatted mmm dd) — the brief specifies yyyy-mm-dd for CSV reuse in other tools and the display form for the human-facing formats.
- The report preview is the generated model rendered as an HTML table (plus the header facts), not an embedded PDF — it previews identically for all three formats and works on iOS Safari, where inline PDF preview is unreliable.
- Backup export includes soft-deleted rows and import restores records verbatim (ids and timestamps kept) — a backup is a device-level safety net, and exactness makes the export → wipe → import round trip testable to the row.
- Import replaces local data (after an explicit confirm that shows the backup's day/leg counts) rather than merging — the brief frames import as a restore, and merging two histories could resurrect deleted days or break leg chains.
- Import clears the outbox and re-queues every restored record, but does not touch the server copies of records that are not in the backup — the server is a mirror of the user's account, and deleting account data from a local restore is beyond what the brief authorizes.
- The backup reminder is due when the last export is missing or older than 7 days (meta key lastExportAt, written on each export) — the brief's "once a week" gentle reminder, evaluated where the user can act on it: the Settings backup section.
- PWA icons are generated (scripts/generate-icons.py, Pillow) rather than designed assets: theme blue, bold white "M", road dashes — they only need to be real, legible PNGs at the manifest's sizes, and the generator keeps them reproducible.
- 2026-10-23: PWA icon PNGs are stored in the repo as base64 (`assets/icons/*.b64`) and decoded into `public/` by `scripts/write-icons.mjs` on every build (`prebuild`), because the GitHub push tooling available to the agent transfers text files only. `scripts/generate-icons.py` remains the design source that produced the base64. Supersedes the Phase 5 note implying the PNGs are committed directly.
- The sign-in screen also redeems a pasted magic link (or a 6-digit code from the email) in-app via verifyOtp / exchangeCodeForSession — an iOS Home Screen app is storage-sandboxed from Safari/Chrome, so a tapped link creates the session in the browser where the installed app can never see it; this is the brief's same magic link, redeemed inside the app instead of opened. The UI warns the link is single-use: it must be copied from the email and pasted before being opened anywhere, or it is consumed by the browser.
- 2026-10-23: The PDF header block no longer borrows the table's last three columns for its right-hand grid (far too narrow — period dates overprinted the ODOMETER labels and the DISTANCE label overprinted its value in a real user report). `computePdfHeaderLayout` measures every header string with the actual font (jsPDF getTextWidth) and sizes three real columns — period date | label | value — anchored to the right margin; the DISTANCE and totals labels centre over the date+label span, which is widened to fit the widest of them, and the header font shrinks in half-point steps if the block would exceed its width budget. The Claimable table column was likewise widened to its measured header width (taken from the address columns) so it never wraps mid-word. Verified visually against rendered fixture PDFs (A+B and C).
- 2026-10-23: Phase 6 visual verification drove the production build in Playwright with fixture data loaded through the app's own flows (first-launch profile form, then a Settings backup import), screenshotting every main screen at 360/390/430 px in light and dark plus a 200%-text pass (root font size doubled via inline style, which is what actually scales the rem-based layout), with automated no-overflow / ≥44px-target / every-control-labelled checks on every shot — chosen because every defect this project shipped to the user (PDF header overlap, date-picker overlap) was visual, not logical.
- 2026-10-23: The install hint's dismiss button now has width: auto — the shared .button style is width: 100% for stacked actions, and inside the hint's flex row it claimed the whole banner, squeezing the text into a sliver and bursting the border at every width and theme (found in the Phase 6 screenshots, present since Phase 4).
- 2026-10-23: The History From/To grid uses repeat(auto-fit, minmax(min(100%, 9.5rem), 1fr)): the rem minimum grows with text size, so under large system text the pair stacks full-width before the native date control can clip its own year; a max-width media query in em was rejected because media-query em follows the browser's initial font size, not the rendered text size doing the squeezing. At default text size the side-by-side layout is unchanged at 360–430 px.
- 2026-10-23: Dark mode danger (delete) colour is the pale tint #f2b8b5 (11:1 on the dark background) instead of the light-scheme red #b3261e (2.9:1, below WCAG AA); the override sits after the base .button-danger rule so it wins the cascade — the first attempt placed it earlier and silently lost, caught by sampling the rendered pixels.
- 2026-10-23: Date headers on Today, Start Day, day review and day summary use the single "Fri, Oct 23, 2026" format (formatFullDateLabel), extending the Phase 5 History-row fix to the same duplicated pattern ("Oct 23 · 2026-10-23"); report date columns keep the brief's "Jul 02" form.
- 2026-10-23: An explicit :focus-visible outline (theme blue in light, pale blue in dark) replaces reliance on the browser default, so keyboard focus is guaranteed visible in both colour schemes.
